# Раздел «Маркетинг» для дашборда РОПа

## Цель

Добавить в существующий дашборд РОПа самостоятельный раздел для контроля
эффективности рекламы Meta Ads. Раздел не связывает рекламу с продажами и не
рассчитывает CAC, ROAS или конверсию в бронь.

## Исходные данные

Первая версия использует две недельные выгрузки Meta Ads:

- 20–26 июля 2026 года;
- 17–23 августа 2026 года.

Каждая строка выгрузки описывает рекламную кампанию и содержит период,
название кампании, статус, тип результата, расход, показы, охват, частоту,
клики, CTR, CPC, CPM и связанные показатели результата.

Выгрузки являются недельными срезами. Они не считаются полными месячными
отчётами и не сверяются с месячными суммами рекламных удержаний из отчёта
продаж.

## Границы первой версии

Раздел показывает только эффективность рекламы. Он не:

- сопоставляет рекламные кампании с клиентами, бронями или менеджерами;
- вычисляет продажи с рекламы, CAC, ROAS и маркетинговую прибыль;
- распределяет расходы между сотрудниками;
- складывает разные типы результата в один показатель;
- подменяет существующие рекламные удержания в финансовой части дашборда.

## Архитектура данных

Парсер рекламных выгрузок преобразует строки Excel в единый набор кампаний.
Для каждой строки сохраняются:

- начало и конец периода;
- название и статус кампании;
- исходный тип результата Meta;
- нормализованная категория результата: лид, звонок, переход по ссылке,
  просмотр посадочной страницы, посещение профиля или другой результат;
- расход, показы, охват, частота, CPM;
- клики по ссылке, CPC ссылки и CTR ссылки;
- все клики, общий CPC и общий CTR;
- просмотры посадочной страницы и стоимость просмотра;
- количество результатов и стоимость результата.

Строки без расхода сохраняются для таблицы кампаний, но не влияют на суммы и
взвешенные показатели. Строка общего итога Meta, если она присутствует без
названия кампании, используется только для показателей, которые нельзя
безопасно суммировать по кампаниям, например уникального охвата.

## Правила расчёта

- Расход, показы и клики суммируются по выбранному периоду.
- CPM рассчитывается как `расход / показы × 1000`.
- CPC ссылки рассчитывается как `расход / клики по ссылке`.
- CTR ссылки рассчитывается как `клики по ссылке / показы × 100%`.
- Лиды и CPL считаются только по кампаниям с результатом типа «лид».
- CPL рассчитывается как расход лидовых кампаний, делённый на число лидов.
- Звонки, переходы, просмотры страницы и посещения профиля показываются
  раздельно.
- Значения разных типов результата не складываются в общий показатель
  «Результаты».
- Охват не суммируется по кампаниям: одни и те же пользователи могут входить
  в охват нескольких кампаний.
- При отсутствии знаменателя производный показатель показывается как «—», а
  не как ноль или бесконечность.

## Периоды

В интерфейсе есть режимы «Неделя» и «Месяц».

В недельном режиме пользователь выбирает одну фактическую выгрузку. Сравнение
выполняется с предыдущей доступной неделей только по сопоставимым метрикам.

В месячном режиме данные всех загруженных недель календарного месяца
объединяются. Если загружены не все дни или недели месяца, рядом с периодом
показывается заметная метка «Неполный месяц». Неполный месяц разрешено
просматривать, но он не должен выглядеть как окончательный месячный итог.

При сравнении периодов интерфейс предупреждает, что состав и цели кампаний
могут отличаться. Лиды и CPL сравниваются только по лидовым кампаниям.

## Интерфейс

Раздел «Маркетинг» добавляется в навигацию РОПа и не показывается в личном
режиме менеджера.

### Верхняя панель

- переключатель «Неделя / Месяц»;
- выбор доступного периода;
- отметка полноты месяца;
- краткое указание источника: Meta Ads.

### Основные показатели

Первая группа карточек:

- расход;
- показы;
- CPM;
- клики по ссылке;
- CPC ссылки;
- CTR ссылки.

Каждая карточка показывает изменение относительно предыдущего сопоставимого
периода, если он существует.

### Лиды

Отдельный блок содержит:

- количество лидов;
- расход лидовых кампаний;
- CPL.

Так лиды не смешиваются с трафиковыми результатами.

### Другие результаты

Звонки, переходы по ссылке, просмотры посадочной страницы и посещения профиля
выводятся отдельными строками с количеством результата, расходом кампаний и
стоимостью соответствующего результата.

### Кампании

Таблица содержит:

- название кампании;
- категорию и исходный тип результата;
- статус;
- расход;
- количество результата;
- стоимость результата;
- показы;
- клики по ссылке;
- CTR ссылки;
- CPM.

По умолчанию кампании сортируются по расходу по убыванию. Кампании без расхода
можно скрыть отдельным переключателем, но они остаются доступными для аудита.

## Сосуществование с финансовыми данными

Существующий блок рекламных расходов в отчёте продаж остаётся финансовым
показателем из исходной книги продаж. В интерфейсе он называется
«Рекламные удержания по отчёту продаж», чтобы его не путали с расходом Meta за
выбранную неделю.

Маркетинговый раздел использует только фактические значения из рекламных
выгрузок. Значения `$786` за июль и `$1 277` за август не используются для
оценки эффективности кампаний и не сравниваются с неполными недельными
выгрузками.

## Ошибки и качество данных

- Файл с отсутствующими обязательными столбцами отклоняется с перечнем
  отсутствующих заголовков.
- Числовые ячейки с пустым значением считаются отсутствующими, а не нулевыми,
  если ноль нельзя доказать из выгрузки.
- Неизвестный тип результата сохраняется как «Другой» с исходным значением.
- Дублирование одной и той же выгрузки определяется по датам периода и
  содержимому кампаний, чтобы итог не удваивался.
- Наличие статуса «Неактивно» не отменяет расходы и результаты внутри периода:
  это состояние кампании на момент формирования выгрузки.

## Проверка готовности

Первая версия считается готовой, если:

1. Июльская и августовская выгрузки импортируются без ручного редактирования.
2. Суммы расходов составляют `$162,05` и `$175,63` соответственно.
3. Лиды составляют `120` и `35`, а CPL — примерно `$0,86` и `$0,61`.
4. Разные типы результата нигде не складываются в одну цифру.
5. Охват не суммируется по кампаниям.
6. Оба периода отмечены как неполные месяцы в месячном режиме.
7. Раздел доступен РОПу и не меняет расчёты продаж, комиссии и рекламных
   удержаний.
8. Страница остаётся работоспособной на GitHub Pages без серверной части.
