# Формат Google-таблицы — источника данных

Этот документ — инструкция для тех, кто ведёт таблицу. Дашборд читает лист
**«Заявки»** и ничего другого. Пока формат соблюдается, цифры сходятся; как
только кто-то добавит колонку в середину или напишет статус своими словами —
строка не загрузится и попадёт в отчёт об ошибках импорта.

## Лист «Заявки» — колонки

| Кол. | Заголовок | Обязательна | Формат | Комментарий |
|------|-----------|-------------|--------|-------------|
| A | `ID заявки` | да | текст | Уникален, **никогда не переиспользуется**. Например `2026-0417`. Это ключ, по которому строка обновляется, а не дублируется |
| B | `Дата обращения` | да | `ДД.ММ.ГГГГ` | Когда клиент написал/позвонил. Знаменатель конверсии |
| C | `Менеджер` | да | текст из выпадающего списка | Должен совпадать с `sheet_alias` в профиле |
| D | `Клиент` | да | текст | ФИО |
| E | `Телефон` | нет | `+998XXXXXXXXX` | По нему склеиваются повторные обращения одного клиента |
| F | `Источник` | нет | список | Instagram / WhatsApp / Сайт / Рекомендация / Повторный |
| G | `Направление` | нет | список | Турция, ОАЭ, Египет, … |
| H | `Туроператор` | нет | список | |
| I | `Туристов` | нет | целое | По умолчанию 1 |
| J | `Дата вылета` | нет | `ДД.ММ.ГГГГ` | Нужна для блока «ближайшие вылеты» |
| K | `Дата возврата` | нет | `ДД.ММ.ГГГГ` | |
| L | `Валюта` | да | `USD` / `UZS` / `EUR` | |
| M | `Курс` | да | число | Курс к базовой валюте на дату брони. Для базовой валюты — `1` |
| N | `Сумма от клиента` | да | число | Брутто. Без пробелов и знаков валюты |
| O | `Себестоимость` | да | число | Нетто — сколько ушло оператору |
| P | `Статус` | да | список | Только из перечня ниже |
| Q | `Дата брони` | если статус ≥ бронь | `ДД.ММ.ГГГГ` | **Момент засчёта продажи** |
| R | `Дедлайн доплаты` | нет | `ДД.ММ.ГГГГ` | Дата, до которой надо доплатить оператору |
| S | `Дата полной оплаты` | если статус «Оплачено» | `ДД.ММ.ГГГГ` | |
| T | `Дата аннуляции` | если статус «Аннуляция» | `ДД.ММ.ГГГГ` | |
| U | `Причина аннуляции` | нет | текст | |
| V | `Комментарий` | нет | текст | |

Комиссия агентства **не вводится руками** — она считается как
`Сумма от клиента − Себестоимость`. Так исключаются расхождения между
таблицей и дашбордом.

## Допустимые статусы

`Новая` · `В работе` · `Расчёт отправлен` · `Бронь` · `Предоплата` ·
`Оплачено` · `Вылет состоялся` · `Аннуляция`

Их нужно завести как выпадающий список (Данные → Настроить проверку данных),
иначе неизбежно появятся «бронь✅», «Бронь!» и «забронирована».

## Правила ведения

1. **Не вставлять и не удалять колонки.** Импорт читает по заголовку, но при
   изменении набора колонок обязательно предупредить разработчика.
2. **Не переиспользовать `ID заявки`.** Иначе старая сделка молча
   перезапишется новой.
3. **Не удалять строки.** Ошибочную заявку помечать статусом `Аннуляция`.
   Удалённая строка перестанет обновляться в БД, но останется в дашборде.
4. **Числа — числами.** `1 250` с пробелом и `1250 USD` не распарсятся.
5. Один лист = все заявки. Не заводить отдельный лист на каждый месяц.

## Как работает синхронизация

* Доступ: сервисный аккаунт Google, таблица расшарена на него **на чтение**.
  Записывать в таблицу дашборд не будет никогда.
* Расписание: каждые 15 минут + кнопка «Обновить сейчас» у РОПа.
* Идемпотентность: по каждой строке считается хеш. Не изменившиеся строки
  пропускаются — прогон дешёвый даже на десятках тысяч строк.
* Ошибки: строка с непарсящейся датой или неизвестным менеджером не валит
  импорт целиком. Она попадает в `sync_errors`, РОП видит плашку
  «14 строк не загружено» со списком и номерами строк.
* Все загруженные данные складываются в свою БД. Дашборд считает метрики
  по ней, а не ходит в Google API на каждый клик, — иначе упрёмся в квоты
  и получим секундные задержки.

## Путь дальше

Google Sheets — стартовый источник, не конечный. Когда дашборд приживётся,
ввод заявки переносится в само приложение (форма + те же поля), а лист
остаётся как экспорт для бухгалтерии. Схема БД уже к этому готова: поле
`source_system` в `deals` отличает импортированные строки от заведённых
в интерфейсе, поэтому переходить можно постепенно, менеджер за менеджером.
