# Turon B2C — дашборд отдела продаж

Панель управления продажами туристического агентства с разграничением по
ролям: руководитель отдела видит картину по всей команде, менеджер — только
свои показатели.

Источник данных на первом этапе — Google-таблица с заявками.

## Документы

| Файл | Что внутри |
|---|---|
| [`docs/tz.md`](docs/tz.md) | Техническое задание: роли, метрики и формулы, состав экранов, стек, дизайн-система, этапы |
| [`docs/google-sheets-format.md`](docs/google-sheets-format.md) | Формат листа-источника и правила его ведения — для тех, кто ведёт таблицу |

## Статус

Этап проектирования. Схема данных и ТЗ готовы, реальный отчёт разобран
(105 сделок за май–июль 2026), собран интерактивный прототип на этих данных.
Код боевого приложения ещё не написан.

## Прототип

```bash
pip install openpyxl
python3 scripts/parse_report.py "Отчет по продажам.xlsx" -o data/deals.json
python3 scripts/build_dashboard.py     # соберёт prototype/dashboard.html
```

Прототип — один самодостаточный HTML-файл: данные вшиты внутрь, сервер не
нужен, открывается двойным кликом.

## Как развернуть базу

```bash
psql "$DATABASE_URL" -f db/schema.sql
psql "$DATABASE_URL" -f db/rls.sql
```

Схема рассчитана на PostgreSQL 15+ и предполагает Supabase Auth
(таблица `auth.users`).

## Персональные данные

`data/*.json` и собранный `prototype/dashboard.html` содержат ФИО клиентов,
поэтому исключены из репозитория через `.gitignore`. Оба файла собираются
локально из исходного отчёта командами выше. В самом прототипе есть
переключатель «Скрыть имена клиентов» — для показа на проекторе и в записи
экрана.
